# WebROMS

ブラウザ内で実際のROMSを実行する海洋モデル作業環境です。コンパイル済みの `runtime/roms.wasm` を同梱しています。利用者にFortran、Python、計算サーバーは不要です。代替のJavaScript流体ソルバーは使用しません。

## 起動

Windowsでは、cloneしたフォルダーの `start-webroms.bat` をダブルクリックするとブラウザーが開きます。Windows標準のPowerShellが同梱ファイルから `dist/` を自動生成するため、Node.js・pnpmのインストールや事前ビルドは不要です。GitHubのソースZIPを全体展開した場合も同じ手順です。

ビルド済みの `WebROMS-windows.zip` も、全体を展開して `start-webroms.bat` から起動できます。対応条件とトラブル対処は [Windows起動ガイド](WINDOWS.md) を参照してください。

Node.jsでの開発・自動テストにはNode.js 22以上とpnpmが必要です。取得したプロジェクトのフォルダーで以下を実行します。

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm dev
```

表示されたURL（通常 http://localhost:5173 ）を開きます。このウィンドウを閉じるとWebROMSも停止します。

WorkerとWASMのためHTTP配信が必要で、HTMLの直接オープンには対応しません。Windows配布ZIPは `pnpm package:windows` でビルド・検査して生成し、`pnpm test:windows` でZIPからの起動と計算を検証します。Web公開対象は `dist/` 全体です。

## 計算の流れ

1. 海底地形: 格子・15層までの鉛直格子、地形プリセット、Shape入出力、ブロック編集、沿岸陸セルの河口配置。
2. 生態系モデル: NPZD・NEMUROの反応図、微分方程式、反応係数。不要ならスキップ。
3. 初期条件: 該当地域の夏季・冬季・通年平均、模擬成層、生物濃度の分布。3Dの側面と拡大可能な鉛直断面を確認。
4. 境界条件: 既定は初期場からの指定値。閉鎖・周期も選択。高度な設定に潮汐APIの参照用推定。
5. 河川の設定: 河川別の流量・水温・塩分・栄養塩等を設定。河川なしならスキップ。
6. 風の強制力: 一様風・風成循環・沿岸風・NOAA風気候値、1セル単位のU/V編集。
7. 定常計算: コリオリ・β平面、時間積分、保存間隔を設定。結果は期間・間隔を選んでNetCDFまたはShape ZIPで出力。

入出力仕様、気候値の対象地域、換算の仮定、潮汐APIの対応範囲は [7工程版の説明](WORKFLOW.md) を参照してください。KINACOは未対応です。

初期条件と定常計算の断面位置は、3D・平面図のピンクのラインで確認できます。夏季・冬季の混合設定は躍層位置と厚さも変え、層数に応じた層平均で表現します。NOAA風データの期間・ENSO事例・解像度、風応力の換算、回転係数の式は [風・回転・成層の説明](FORCING.md) を参照してください。

地形は最大15層、水深10,000 mまで設定できます。ブロック編集はブラシ内の地形を1マス分ずつ変更し、「戻す」「進める」に対応します。河川は沿岸の陸セルを選び、隣接する内部の海セルへ、流量・水温・塩分・生物濃度をROMSの体積源として与えます。閉鎖水槽に流入を与えると水位が上昇します。

瀬戸内海・大阪湾・東京湾・伊勢湾、日本周辺、北太平洋東岸、太平洋・大西洋の南北のサンプルは、NOAA ETOPO 2022の地形データを間引いて同梱しています。海岸線と水深は元データに基づき、設定水深で制限されます。格子数による海峡・島の省略、平面格子への近似などの制約は [地形サンプルの説明](TERRAIN.md) を参照してください。風応力と回転の設定は循環・湧昇の実験用で、実海域の再現や定常循環の成立を保証しません。

NOAA WOA23の通年・夏季・冬季プロファイルを同梱し、オフラインで適用できます。ENSOはGODASの選択した各3事例の冬季合成値で、全事例の気候値ではありません。深層の代替値、対象期間、出典・再取得方法は [気候値の説明](CLIMATOLOGY.md) を参照してください。mg表示はレッドフィールド比 C:N:P = 106:16:1 による元素相当量で、乾燥重量ではありません。

3D・平面・断面表示、設定の保存と読込、結果NetCDF・Shape ZIPのダウンロードに対応します。設定変更時は古い計算結果を無効化します。

## 計算核と範囲

### 生態系の設定

「生態系モデル」でNPZD (Franks)・NEMUROを選択できます。モデル別の初期濃度、境界面の濃度、格子への塗布、プレビュー、JSON保存に対応します。NPZDは4状態量と13反応パラメータ、NEMUROは11状態量と84反応パラメータを設定できます。

NPZDの既定値はROMS `npzd_Franks.in`、NEMUROの反応パラメータは`nemuro.in`に基づきます。NEMUROの初期濃度のみ`roms/sample/NEMURO.BOX.f90`のA7サンプルに基づき、mol/Lからmmol/m³へ換算しています。サンプルの反応式や全パラメータを移植したものではありません。状態量・塗布値はモデル別に保存されます。

NPZD・NEMUROは専用WASMを同梱し、ROMS本体で反応・移流・拡散・沈降を時間積分します。「生態系モデル」でモデルと反応係数、「初期条件」で濃度を設定してください。「境界条件」で各濃度を設定し、「定常計算」から実行できます。NEMUROでは海面の短波放射（W/m²、時間・空間一様）も設定できます。結果の表示項目から各生物濃度を選べます。

NEMUROの摂餌方式はROMSの`IVLEV_EXPLICIT`です。生物トレーサーの外部からの海面・海底フラックスはゼロ、粒子の沈降は各モデルの沈降速度に従います。生態系の計算をスキップすると物理計算用WASMを使います。

ROMS 4.3、コミット `57aecf589a408b1e5490d2db7f9bd0196062a44e` のFortranコードをFlang/EmscriptenでWASM化しています。海面高度、3次元流速、温度・塩分、移流、水平・鉛直拡散、陸域のC格子マスクをROMSが計算します。NetCDF入出力もWASM内で実行します。

現在は直交格子、2～15等分sigma層、固定陸域、静水圧近似の選択構成です。大気熱・淡水フラックスはゼロ、底面は線形抵抗です。濡れ乾き、潮汐データ同化、入れ子格子、任意のROMSコンパイルオプションには対応していません。急峻な海底、不整合な境界、過大な時間刻みでは発散し得ます。

計算は指定したステップ数まで実行し、通常計算中の履歴保存はしません。終了後の「結果のダウンロード」で時間・保存間隔を指定すると、その状態から保存用の追加RUNを実行します。0時間なら終了場だけを出力します。許容残差による自動終了はなく、「計算完了」は定常状態への到達を保証しません。手動中断・計算エラーでの停止は引き続き有効です。

## 検証

```sh
pnpm test
pnpm build
pnpm check:release
pnpm exec playwright install chromium
pnpm test:browser
```

一様場、陸域と風応力、鉛直拡散の8×8×3格子・100ステップについて、同一入力のネイティブgfortran版と比較済みです。比較記録は `validation/`、配布物のハッシュとツールチェーンは `runtime/manifest.json` にあります。指定値・放射・周期境界、ブラウザの実計算と結果保存も自動テストします。この限定した検証は全構成の同値性を保証しません。

NPZD・NEMUROも8×8×3格子・60ステップ（1時間）の閉鎖一様水槽でネイティブ版と比較し、全出力の最大絶対差はそれぞれ0と約5.6×10⁻¹⁷でした。光量・反応係数への応答、沈降を止めた場合の窒素保存、生物濃度の拡散、陸域付近、指定値・放射・周期境界を自動テストします。Windows配布ZIPは外部通信なし・Node.jsなしの起動とEdgeでの両モデル実計算を検証しています。

## GitHub公開

GitHub登録後、Settings > Pages > Sourceを **GitHub Actions** に設定し、`Publish Pages` ワークフローを手動実行します。テストと配布物検査後に静的サイトを公開します。通常のpush/PRではCIだけが動作します。

`roms/`、`.tools/`、`node_modules/` は公開対象外です。同梱WASM、manifest、ライセンスは必ず含めてください。詳細は [設計](BROWSER_ROMS_DESIGN.md)、[第三者ライセンス](THIRD_PARTY_NOTICES.md) を参照してください。
